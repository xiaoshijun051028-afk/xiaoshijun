# GDD · 核心战斗系统 (Combat)
> 系统编号 S1 ｜ 版本 v0.3 ｜ 依赖 S3(共鸣池) ｜ 上游 概念文档 v0.2
> v0.3 变更（T5-DESIGN-b）：收口时间膨胀语义——终结技**不**进入慢动作（D-AUD-1）；完美格慢动作补 `time_scale` 比值与计时基准（D-AUD-2）。常量见 systems-index §2。

## ① 概述与目标
玩家以"星刃"进行 6 动词近战：斩 / 闪 / 荡 / 跃 / 格 / 共鸣（共鸣终结技消耗 S3 池）。目标：兑现支柱 P1「流动即正义」（≤8 帧取消窗口的连段手感）、P4「共鸣统一」（终结技共用池）、美学 Challenge（精确读招）。防认知过载：6 动词共用一套取消/预警语言。

## ② 核心机制/规则
- 动词状态机：idle → {slash, dash, grapple, leap, parry, resonate}；任意动作收招在 `CANCEL_WINDOW=8f` 内可接续另一动作（闪可取消斩收招；跃可取消闪；格可接斩反击）。
- 斩：轻击 4 段连段，重击蓄力；最后一段可接共鸣终结技。
- 闪：位移 + `DASH_IFRAMES=10f` 无敌；完美闪（结束前 3f 内命中敌人）触发极短缓时（hit-stop 延长）。
- 格：在 `PARRY_WINDOW=6f` 内挡下 telegraph 攻击 → 破防（敌人硬直 1.2s = 72f）+ **慢动作 `PARRY_SLOWMO_FRAMES=18f` / `PARRY_SLOWMO_SCALE=0.3`** + 共鸣 +5。
  - 18 帧按**真实时间（墙钟 300 ms）**计，非游戏 tick；`Engine.time_scale` 在此期间 = 0.3，结束精确回 1.0。完整计时基准与实现约束见 systems-index §2。
- 命中反馈：hit-stop 60–90ms + 轻微震屏；重击附加落地冲击波判定。
- 共鸣终结技：池 ≥ `FINISHER_COST` 时，斩终段接续共鸣 → 全屏谐波脉冲，高伤 + 击退。
- **终结技不进入慢动作**（D-AUD-1 定夺，见 §⑧）：终结技全程 `Engine.time_scale` 恒 = 1.0，**不触发任何时间膨胀**。其冲击完全由「全屏谐波脉冲 + 高伤 + 击退 4m + 命中 hit-stop」承载。
  - **全作时间膨胀语义唯一归属完美格挡**——这是刻意的稀缺性设计，不是遗漏。终结技=资源倾泻的爽感，完美格=精确读招的奖励，两者反馈语言必须可区分。

## ③ 状态与数据流
- 玩家状态：HP(0–100)、combo(0–4)、hitstun(0/1)、iframe(0/1)、parryArmed(0/1)、resonance(见 S3)。
- 数据流：输入 → FSM 判定（查 CANCEL_WINDOW/IFRAMES/PARRY_WINDOW）→ 命中计算 → 敌人 HP↓/玩家 HP↓ → 共鸣池增减（S3）→ HUD(S6) 刷新。
- 持久化：HP/combo 不持久；共鸣池随神龛存档（S8）。

## ④ 与其他系统接口
- → S3：终结技扣 `FINISHER_COST`；池不足禁用。
- → S2：闪/跃为移动动词，共享取消窗口与手感。
- ↔ S4：敌人 telegraph 显 `THREAT`；格挡判定联动破防。
- → S6：暴露 hp/combo/iframe/resonance 供 HUD。
- → S8：技能树可改取消窗口/伤害/完美闪奖励（Should）。

## ⑤ 数值/参数初值（可落地范围）
- 玩家 HP = 100。
- 斩轻击 8–12 dmg/段；重击 18–25 dmg；4 段连段总 ≈ 40–60。
- 闪：距离 4–6 m，cd 0.4s，iframes 10f。
- 跃：起跳高 3–4 m，悬停 0.4s，落地震波半径 2–3 m。
- 格：窗口 6f，破防硬直 72f (1.2s)，慢动作 `PARRY_SLOWMO_FRAMES=18f`（0.3s 真实）@ `PARRY_SLOWMO_SCALE=0.3`。
- 终结技：cost 40，dmg 60–90（视连段数），击退 4 m，**慢动作 = 无**（`time_scale` 恒 1.0）。
- 取消窗口 8f（全局上限，技能树最多降到 5f）。

## ⑥ 边界与失败处理
- 输入缓冲溢出：同时按 ≥3 键时，优先 格 > 闪 > 斩，丢弃多余输入（防误操作）。
- 共鸣不足终结技：灰显并提示"共鸣不足"，不进入共鸣态。
- 无敌帧重叠：闪 iframes 期间不受任何伤害；格窗口外被击中正常扣血。
- 坠落死亡：跃出边界 → 触发神龛复活（S8）。
- 硬直锁：hitstun 期间禁输入，最长 0.5s 防卡死。
- 多敌围攻：单次闪 iframes 对所有敌人生效，不区分来源。
- **慢动作 × hit-stop 叠加**：慢动作期间发生命中 hit-stop（架构 §5.4 `frozen_frames`，非 `time_scale`）→ 二者**独立不相乘**。hit-stop 按 tick 冻结优先；冻结结束后慢动作按**剩余墙钟时长**继续，不因冻结而延长。
- **慢动作嵌套/刷取**：慢动作生效中再次完美格挡 → **不叠加、不加深**，只把剩余时长**重置**为 18 帧，`time_scale` 维持 0.3。防连续格挡把战斗拖成永久慢放（同时堵死"靠连格获得持续慢动作"这一主导策略）。
- **慢动作 × 暂停/场景切换**：慢动作期间进暂停（ux-spec §4.1 用 `Engine.time_scale=0`）→ 记录剩余墙钟时长，恢复时续算；**退出至主菜单/神龛复活/读档一律强制 `time_scale = 1.0`**，防慢动作状态泄漏到菜单或下一局。
- **终结技期间禁膨胀**：若终结技释放帧恰好落在完美格慢动作窗口内 → 慢动作**按原剩余时长自然走完**，终结技本身不新增、不延长、不打断膨胀（终结技对 `time_scale` 只读不写）。

## ⑦ 可测试性（验收标准）
- [ ] 测量任意两动词间取消延迟 ≤ 8 帧（自动化录屏帧分析）。
- [ ] 连段中断率 < 5%（20 名玩家原型测试）。
- [ ] 完美格触发慢动作 + 敌人硬直 ≥ 1s。
- [ ] **完美格慢动作精度**：`Engine.time_scale` 命中 0.3（±0.01），持续 **300 ms 墙钟**（±1 帧 / ±17 ms），结束后精确恢复 1.0（断言 `is_equal_approx(1.0)`）。
- [ ] **终结技零膨胀（D-AUD-1 回归测试）**：终结技释放前/中/后全程采样 `Engine.time_scale` 恒 = 1.0；且 `time_dilation_started` 信号**不被终结技发出**。
- [ ] **慢动作不泄漏**：暂停/退主菜单/复活/读档后 `Engine.time_scale == 1.0`；连续 3 次完美格挡后总膨胀时长 ≤ 单次 18 帧×3（无嵌套加深）。
- [ ] 共鸣不足时终结技不可释放且 HUD 灰显。
- [ ] 闪 iframes 期间 0 伤害（单元测试注入攻击）。

## ⑧ 开放问题与决策记录

### 已决策

**D-AUD-1 ｜ 终结技是否触发慢动作 → 否（v0.3 定夺，文策渊）**

背景：audio-direction §8.2 / CONCERN-AUD-1 指出音频派单假设"终结技触发慢动作"，但本 GDD §② 从未定义该条。现正式定夺为**否**，并在 §② 显式写明，避免被当作遗漏而反复重开。

判定理由（四条）：
1. **时间膨胀语义唯一性**：慢动作是稀缺的表达货币，全作**只归属完美格挡**——它是"精确读招"的奖励。若终结技共用同一语言，完美格的独特性被稀释，反馈系统同质化（支柱漂移风险）。
2. **守 P1「流动即正义」**：终结技是斩 4 段末段的**连段接续点**，其前后仍在 `CANCEL_WINDOW=8f` 的流动语境中。插入 18 帧时间膨胀会砸断连段节奏与后续接战衔接。反观完美格本身就是"停顿—反击"节拍，与膨胀天然相容。
3. **守 P4 取舍中立（防主导策略）**：单一共享池下「解谜开门 `GATE_COST=30`」与「终结技 `FINISHER_COST=40`」必须在体验价值上势均力敌（systems-index §2 明写"防主导策略"）。给终结技追加慢动作 = 单方面加码感官奖励，会让玩家系统性偏向终结技，直接削弱 P4 的机会成本张力（也削弱 audio-direction §4.2 精心设计的"互斥张力听觉化"）。
4. **实现确定性 + 可访问性**：架构 §5.4 的 hit-stop 用 FSM `frozen_frames` 而非 `time_scale`；终结技为全屏 AoE，命中多敌会连发 hit-stop。若再叠全局 `time_scale`，会产生"冻结帧 × 时间缩放"的叠加，总时长不可预测、难以调校与测试。同时，减少时间膨胀触发源可降低前庭不适负担，简化可访问性 F5 动效滑块的覆盖面。

影响面（无需他人返工）：
- **阮和鸣**：音频侧"可插拔"层保持**未触发**即可，`time_dilation_started` 仅由完美格挡发出；audio-direction §8.4⑤ 特写层表中"终结技（若将来加入慢动作）"一行保留为**假设分支、v1 不启用**，无需修改。
- **systems-index §2**：**不新增** `FINISHER_SLOWMO*` 常量，仅留一行否定说明。
- 若未来要推翻此决策，须同时复核 P1（连段流动）、P4（开门↔终结技取舍中立）、可访问性 F5，并补齐 `FINISHER_SLOWMO_FRAMES` / `FINISHER_SLOWMO_SCALE` 与本节全部边缘情况。

**D-AUD-2 ｜ 完美格慢动作 `time_scale` 比值与计时基准 → 0.3 / 18 帧墙钟（v0.3 定夺）**

- `PARRY_SLOWMO_SCALE = 0.3`：足够读出"世界慢下来"，又不至于像 0.1 那样近乎冻结；与 audio-direction §8.4 已调好的低通下潜（SFX→1800 Hz / 40 ms）听感强度匹配。
- `PARRY_SLOWMO_FRAMES = 18`（= 300 ms **墙钟真实时间**）。**这是本次最关键的消歧**：若把 18 帧按游戏 tick 计，实际真实时长会变成 `18 / 0.3 = 1.0 s`，将吞掉 72 帧（1.2 s）破防窗口的绝大部分，并使 `CANCEL_WINDOW=8f` 在真实观感上被放宽约 3.3×——那等于给每次完美格挡偷偷发一张"辅助模式"券，**违反 ux-spec §5.1 已拍板的「默认不放宽取消窗口」**。按墙钟计后，膨胀期内仅约 5.4 游戏帧流逝，8f 窗口的真实观感上限约 340 ms（有界、可接受，且是对 6 帧精度操作的正当奖励）。
- 计时实现约束与"0.3 数值巧合"警告见 systems-index §2。

**D-G8 ｜ lock-on 摄像机 → 做**（用户已拍板，见 ux-spec §2）。lock-on 位于相机/目标锁定层，**不进入本 FSM**、不消耗 `CANCEL_WINDOW`；对闪/荡的方向语义影响见 ux-spec §2.5。本条为跨文档同步，非新决策。
