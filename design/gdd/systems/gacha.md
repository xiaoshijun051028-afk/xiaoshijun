## §1 系统定位与玩家体验（MDA）

### 1.1 一句话定位

**星轨召唤**是一个**据点层的角色收集系统**：玩家消耗货币从"星轨"中召唤**残响旅人**（可玩角色），每名角色拥有不同的五维数值与共鸣亲和；在神龛/关卡前选定一名出战。它把"重复游玩同一批浮岛"从**内容消耗**转变为**配装表达**。

### 1.2 为什么一个单人动作冒险需要它（诚实回答）

单人 ACT 最真实的风险是：**内容一次性消耗完，玩家没有回访理由**。概念 §5 的 v1 内容量（1 中枢岛 + 3–4 浮岛 + 1 Boss）约 12–15 小时，通关后循环即终止。星轨召唤提供的不是"更多内容"，而是**同一内容的新读法**——用不同数值角色重跑同一张岛，战斗解法与空中路线可行性都会变。这是 Solo 项目性价比最高的时长杠杆。

**但它必须付出的代价必须被承认**：每个角色都需要独立的 3D 精美模型/材质（P3 的美术门槛不允许敷衍）。这是本系统**最大的生产风险**，见 §8 待批项 2。

### 1.3 MDA 三层

| 层 | 内容 |
|---|---|
| **Mechanics（机制）** | ① 加权随机抽取表（4 稀有度档）；② 双计数器保底（SSR 软/硬保底 + SR 十连保底）；③ 角色静态定义（archetype 五维基线）；④ 抽取时一次性 roll 并**永久锁定**的副属性浮动；⑤ 双货币（共鸣尘 / 星辉）；⑥ 重复角色 → 尘返还 + roll 重掷权；⑦ 出战角色数值注入 `PlayerCombat`。 |
| **Dynamics（动态）** | ① **"这一抽会不会出"的期待曲线**——保底计数器可见，把随机性转成可规划的进度感；② **配装式重玩**：磐盾角色让玩家敢于正面硬碰，风追角色逼玩家走 P2 纯空中路线，同一张岛涌现不同解法；③ **roll 锁定制造"个体叙事"**——玩家的"那只攻击 +4.8% 的剑主"是独一无二的，产生依恋；④ 谐律角色抬高终结技价值 → 玩家主动囤池 → 与开门需求产生**新的一层 P4 张力**。 |
| **Aesthetics（美学 / LeBlanc 8）** | 强化 **Expression**（角色选择 = 玩法风格宣言，把概念 §2 标为 Should 的 Expression 升为 v1 实装）、**Discovery**（花名册 = 世界观图鉴，每角色带 `lore_text`）、**Sensation**（召唤演出的谐波脉冲）。**明确不追求 Submission（成瘾式日常）**——无每日登录、无限时卡池、无 FOMO 计时器。 |

> **美学取舍**：抽卡在商业手游里主要服务 Submission（习惯性重复）。本作**主动放弃该维度**——这正是"买断制单机"与"F2P 手游"的分野。没有每日任务、没有限时 UP、没有体力值。

### 1.4 自我决定论（SDT）三需求论证

**自主 Autonomy —— 最强契合点**
- 出战角色可**随时在神龛更换，零成本、无冷却**。玩家不被一次抽卡结果锁死。
- 单抽与十连**期望值严格相等**（§4.3），十连只是"一次点完"的便利，不是更优解。玩家按自己的节奏消费，不被最优解绑架。
- 角色不构成 gating：任何角色都能推进主线（`AC-GACHA-05`）。抽卡是**风格选择**，不是**门票**。

**胜任 Competence —— 需要防守的点**
- 风险：数值提升会稀释"靠读招精度获胜"的胜任感，把成就归因从"我变强了"偷换成"我抽到了"。
- 防守做法：**攻击维度乘区被压到 ×1.30 上限**（§3.2），使得敌人所需连段数从 4 段降到最少 2 段——**永远打不出"一击秒杀"**，玩家始终要完整执行连段与闪避。数值改变的是**容错**（HP/防御），不是**技巧需求**。
- 正向增益：稀有度高的角色**共鸣亲和更高 → 终结技更狠**，但终结技依然要靠 4 段连段接续才能打出（`combat.md §②`）。**高稀有度奖励的是"把技巧执行得更彻底"，不是"跳过技巧"**。

**关联 Relatedness —— 补足 Solo 短板**
- 概念 §4 承认 Relatedness 是 Solo 的弱项，原方案靠"残响回声 NPC"补足。**角色花名册是该策略的自然延伸**：每个召唤出的角色是一位**坠落王国的残响旅人**，带 `lore_text` 与专属残响片段（接 S7）。
- 玩家收集的不是"数值卡"，是**幸存者名册**——你在重建这个王国的人。这直接服务概念 §1 的 Fantasy「修复坠落天空王国」。

### 1.5 心流平衡（Flow）

概念 §4 要求「守住高/低技能玩家的心流带」，原方案靠"难度选项 + NG+"。**本系统提供了一个更优雅的替代**：

- **低技能玩家**：抽到磐盾（高 HP/防御）→ 容错窗口变宽 → 焦虑区回落到心流带。这比"选简单难度"心理负担低得多（**玩家不必承认自己菜，是"我玩的是坦克角色"**）。
- **高技能玩家**：主动选择锋刃/风追（低 HP 高攻）→ 自我加难 → 无聊区回升到心流带，且**有数值上的正反馈**（更快的击杀）。
- **关键约束**：**敌人数值绝不随玩家角色缩放**（no rubber-banding / no level scaling）。一旦引入动态缩放，上述两个方向的调节全部归零，且直接违反概念 §4「无等级碾压式 gating」。**这条是硬红线。**

### 1.6 对四大支柱的服务与风险

| 支柱 | 服务方式 | 风险 | 防守措施 |
|---|---|---|---|
| **P1 流动即正义** | 角色差异让同一套连段有不同节奏感（高攻角色 2 连段收，低攻 4 连段收）。 | ⚠ **高**：攻击力膨胀会让敌人秒死，连段打不完，"平均连段长度"指标崩塌。 | 攻击乘区权重压到 **0.5**（SSR 实际仅 ×1.30）；`AC-GACHA-05` 断言全稀有度下击杀标准敌所需连段数 ∈ [2, 4]。**取消窗口 8f 恒定，任何角色不得修改**。 |
| **P2 垂直即世界** | 风追角色移速更高 → 摆荡/跳跃距离更远 → 解锁原本够不到的空中路线，制造"用对角色才能到的地方"。 | ⚠ **极高**：移速是平台跳跃间距的调校基准，浮动过大会让全部关卡间距失效（够不到 = 卡关；跳过头 = 破坏关卡设计）。 | 移速乘区权重压到 **0.1**，全稀有度最终移速被夹在 **[92, 114]**（±15% 内），关卡按 100 基准调校即可全覆盖。**这是工程约束，不是平衡口味**。 |
| **P3 精美即叙事** | 每角色 = 一位残响旅人，视觉与 `lore_text` 承担世界观传达；花名册即图鉴。 | ⚠ **极高（生产成本）**：N 个精美 3D 角色 ≈ 可能超过项目其余全部美术量。 | v1 角色池收窄至 **8 个**，且**共用同一套骨骼与动画集**（只换模型/材质/配色/特效）。见 §8 待批项 2。 |
| **P4 共鸣统一** | 共鸣亲和成为第五维，让"共鸣"从单一池扩展为**角色特质**，深化而非分裂该支柱。 | ⚠ **高**：若亲和提升共鸣**获取速率**，玩家能同时负担开门 + 终结技 → **互斥张力崩塌，P4 当场失效**。 | **裁决：亲和只影响终结技威力，绝不影响共鸣获取量**（§6.3）。成本恒为 `GATE_COST=30` / `FINISHER_COST=40`，稀缺性不变。 |

### 2.2 基础抽取概率（保底前）

以**万分比（basis point, bp）**表达，整数运算，总和恒 = 10000。

| 档 | 概率 | bp | 说明 |
|---|---|---|---|
| 尘 N | 60.00% | `6000` | 保证抽卡有"底噪"，让 R+ 有对比感 |
| 铁 R | 30.00% | `3000` | 主要构成 |
| 辉 SR | 8.50% | `850` | 明确的"好东西" |
| 星 SSR | 1.50% | `150` | 稀有但不折磨（**显著高于手游常见 0.6%**——买断制不需要靠低概率榨取） |
| — | **100.00%** | **10000** | ✅ 校验和 |

### 2.3 软保底 / 硬保底（SSR）

采用**线性爬升**曲线，`pity_ssr` = 距上次出 SSR 的连续未出货抽数。

```
SSR 概率(第 n 抽)：
  n ≤ 73  →  150 bp                       （1.50%，基础值）
  n ≥ 74  →  150 + (n - 73) × 600 bp      （每抽 +6.00%）
```

- **软保底起点 `PITY_SSR_SOFT = 74`**
- **爬升斜率 `PITY_SSR_RAMP_BP = 600`**（+6%/抽）
- **硬保底 `PITY_SSR_HARD = 90`**

**为什么硬保底恰好落在 90**——这不是拍脑袋，是曲线的数学终点：

```
150 + (n - 73) × 600 ≥ 10000
        →  n - 73 ≥ 16.42
        →  n ≥ 89.42
        →  n = 90   ✅ 概率在第 90 抽自然达到 103.5% ≥ 100%
```

即**硬保底不是外挂式的强制覆写，而是软保底曲线的自然收敛点**。工程实现只需 `clamp(p, 0, 10000)`，无需第二套 if 分支——这消除了"软硬保底两套逻辑打架"的整类 Bug。

**出货期望（解析解，供 `AC-GACHA-01` 断言）**

| 指标 | 解析值 |
|---|---|
| 73 抽内不出 SSR 的概率 | `0.985^73 = 33.18%` |
| **平均出货抽数 E[N]** | **≈ 46.1 抽** |
| **综合出货率（含保底）** | **≈ 2.17%** |

### 2.4 SR 保底（十连保障）

```
pity_sr ≥ 9 且本抽未出 SR/SSR  →  强制提升至 SR
```
- **`PITY_SR_HARD = 10`**：`pity_sr` 在出 SR **或** SSR 时归零。
- 效果：**任意连续 10 抽内必得至少 1 个 SR+**。
- ⚠ 注意这是**全局连续计数器**，不是"每一发十连内部"计数。这是消除"十连优于单抽"这一主导策略的关键，详见 §4.3。

### 2.5 稀有度数值乘区（总权力预算乘子）

| 档 | 总乘子 | 千分比常量 |
|---|---|---|
| 尘 N | ×1.00 | `1000` |
| 铁 R | ×1.15 | `1150` |
| 辉 SR | ×1.35 | `1350` |
| 星 SSR | ×1.60 | `1600` |

> ⚠ **关键设计**：这个乘子**不是**直接乘到五维每一项上。若直接全维 ×1.6，P1 与 P2 会同时被击穿（攻击膨胀砸断连段、移速膨胀废掉关卡间距）。它是**总权力预算乘子**，通过 §3.2 的**维度权重**分配下去。

## §3 角色数值模型（核心）

### 3.1 五维定义与量纲

**全部为整数**，其中 4 项是以 100 为基准的**百分比标量**（定点整数，天然满足 60Hz 帧整数与确定性要求）。

| 字段 | 量纲 | 基准 | 作用公式 | 备注 |
|---|---|---|---|---|
| `hp` | 绝对值 | `100`（= 现 `GameConstants.PLAYER_MAX_HP`） | `PlayerCombat.max_hp = hp` | 直接替换现有玩家血量 |
| `attack` | 标量 ‰百分比 | `100` | `伤害 = 招式基础伤害 × attack / 100` | 整数除法 |
| `defense` | 标量 百分比 | `100` | `受击 = 来袭伤害 × 100 / defense` | 整数除法，`defense ≥ 1` 保护 |
| `move_speed` | 标量 百分比 | `100` | `实际移速 = 基准移速 × move_speed / 100` | **关卡调校基准** |
| `resonance_affinity` | 标量 百分比 | `100` | `终结技伤害 = 基础 × clampi(affinity, 80, 200) / 100` | **不影响共鸣获取，见 §6.3** |

> `defense` 公式 `100 / defense` 天然带**收益递减**且**永不为 0**（免疫不可达）：def 166 → 受击 ×0.60；def 83 → 受击 ×1.20。无退化边界。

### 3.2 职阶（Archetype）基线 —— 权力预算 500

四个职阶，其中三个刻意呼应 `meta-progression.md §⑤` 的技能树 3 系（迅捷 / 共鸣 / 守护），使两套成长语言同构、降低认知负担。

**硬约束：每个职阶五维之和必须恒 = 500**（可自动化校验，见 `AC-GACHA-03`）。

| 职阶 | 代号 | hp | attack | defense | move_speed | affinity | Σ | 定位 |
|---|---|---|---|---|---|---|---|---|
| **锋刃** Bladewright | `BLADE` | 95 | **118** | 90 | 102 | 95 | **500** | 高攻脆皮，奖励零失误 |
| **磐盾** Bulwark | `BULWARK` | **115** | 88 | **112** | 92 | 93 | **500** | 高容错，守护系 |
| **风追** Windchaser | `WINDCHASER` | 90 | 110 | 88 | **108** | 104 | **500** | 迅捷系，解锁空中路线 |
| **谐律** Resonant | `RESONANT` | 98 | 95 | 94 | 98 | **115** | **500** | 共鸣系，终结技特化 |

单个角色允许在职阶基线上做 **±3 点**的个体微调（制造角色个性），但**五维之和必须仍等于 500**——这把"数值设计"变成了**零和分配**，从结构上杜绝数值通胀（新角色不可能比老角色"全维更强"）。

### 3.3 维度权重 —— 稀有度乘区如何分配

```
eff_mult_milli(stat) = 1000 + (rarity_milli - 1000) × weight_milli(stat) / 1000
```

| 维度 | 权重 | 千分比常量 | 设计理由 |
|---|---|---|---|
| `hp` | **1.0** | `1000` | 容错维度。提高容错**不稀释技巧表达**，是扩展低技能玩家心流带的正当手段。 |
| `resonance_affinity` | **1.0** | `1000` | 服务 P4 表达。因其只影响"支出产出"、不影响"收入"，不破坏互斥张力。 |
| `defense` | **0.7** | `700` | 容错维度，但与 hp 乘性叠加，需收敛。 |
| `attack` | **0.5** | `500` | ⚠ **P1 守卫**。攻击直接决定敌人存活帧数，全权重会砸断连段。 |
| `move_speed` | **0.1** | `100` | ⚠ **P2 守卫**。移速是关卡跳跃间距的调校基准，几乎不允许浮动。 |

**展开后的实际乘区表**

| 档 | 总乘子 | hp | affinity | defense | attack | move_speed |
|---|---|---|---|---|---|---|
| 尘 N | ×1.00 | ×1.000 | ×1.000 | ×1.000 | ×1.000 | ×1.000 |
| 铁 R | ×1.15 | ×1.150 | ×1.150 | ×1.105 | ×1.075 | ×1.015 |
| 辉 SR | ×1.35 | ×1.350 | ×1.350 | ×1.245 | ×1.175 | ×1.035 |
| 星 SSR | ×1.60 | ×1.600 | ×1.600 | ×1.420 | **×1.300** | **×1.060** |

### 3.4 副属性 roll（抽卡时一次性掷定，永久锁定）

- **适用维度**：`attack` / `defense` / `resonance_affinity` **三项各独立 roll 一次**。
- **不适用**：`hp` 与 `move_speed` **不 roll**。
  - `move_speed` 不 roll 是**工程刚需**——它决定跳跃间距，任何随机都会让关卡可达性不可预测（同一角色随机到 -5% 就够不到某个平台 = 不可复现的卡关 Bug）。
  - `hp` 不 roll 是为**可读性与可测性**——让"这角色几滴血能撑几下"保持确定，便于关卡伤害调校。
- **范围**：`[950, 1050]` 千分比，即 **±5.0%**。
- **粒度**：步长 `5`‰ → 共 **21 个等概率档位**（950, 955, ..., 1050）。离散化避免无意义精度，且让"极品 roll"可被玩家清晰识别。
- **确定性**：roll 在**抽出瞬间**掷定，写入该角色实例并**永久锁定**，随存档持久化。
  - 同一角色两次抽出，数值**可以不同**（这是有意的个体差异，制造依恋）。
  - 一旦锁定，**任何情况下不再变动**（读档、换场景、升级均不重掷）——**唯一例外**：重复角色的"roll 重掷权"（§4.5），且由玩家显式确认。

### 3.5 最终数值公式（整数运算，无浮点）

```
final_stat = archetype_base × eff_mult_milli × roll_milli / 1000000
                                                （整数除法，向下取整）

其中：hp 与 move_speed 的 roll_milli 恒 = 1000
```

> 中间量级：`120 × 1600 × 1050 = 201,600,000`，远低于 GDScript `int`（64 位）上限，**无溢出风险**。
> 运算顺序**必须先乘后除**（先除会丢精度导致断言不稳）。

### 3.7 全局数值边界与支柱验证

| 维度 | 理论最小 | 理论最大 | 跨度 | 边界来源 |
|---|---|---|---|---|
| `hp` | **90**（风追 N） | **184**（磐盾 SSR） | 2.04× | 不 roll |
| `attack` | **83**（磐盾 N, roll 950） | **161**（锋刃 SSR, roll 1050） | 1.94× | — |
| `defense` | **83**（风追 N, roll 950） | **166**（磐盾 SSR, roll 1050） | 2.00× | — |
| `move_speed` | **92**（磐盾 N） | **114**（风追 SSR） | 1.24× | ✅ 落在 `[90, 115]` 工程安全带内 |
| `affinity` | **88**（磐盾 N, roll 950） | **193**（谐律 SSR, roll 1050） | 2.19× | ✅ 低于 clamp 上限 200 |

**✅ P1 验证（连段长度守住）** — 标准敌 `max_hp = 100`，轻击基础伤害 10：

| 角色攻击 | 单段伤害 | 击杀所需命中 | 所需连段（4 段/轮） |
|---|---|---|---|
| 最低 83 | `10×83/100 = 8` | 12.5 | **4 轮** |
| 基准 100 | 10 | 10 | 3 轮 |
| 最高 161 | `10×161/100 = 16` | 6.25 | **2 轮** |

→ 全稀有度下击杀均需 **2–4 轮完整连段**，玩家**永远无法一击秒杀**，P1「平均连段长度」指标不被击穿。
> 对照实验：若攻击用满权重 1.0，SSR 锋刃攻击 = `118×1.6×1.05 = 198` → 单段 19 → 5.3 次命中 → **1.3 轮连段**，连段被打断、P1 当场失效。**这就是权重 0.5 的存在理由。**

**✅ P2 验证**：移速全域 `[92, 114]`，关卡按基准 100 调校后，最慢角色仍有 92% 位移、最快 114%。要求关卡设计遵守：**所有必经跳跃间距按 92% 移速可达**，**所有捷径间距要求 ≥ 108% 移速**（专供风追系）。

**⚠ 已知最大张力 — 有效血量（EHP）跨度**

```
EHP = hp × defense / 100
最脆：90 × 83/100  =  74.7
最肉：184 × 166/100 = 305.4      →  跨度 4.09×
```

按标准敌攻击 20 计：最脆角色 **3 击死亡**，最肉角色 **15 击死亡**。

这是本设计**最大的平衡风险**，我不粉饰它。防守与调参：
1. **硬门禁**：`AC-GACHA-05` 要求 N 卡可通关全部 v1 内容——保证 EHP 下限侧不构成 gating。
2. **敌人不做任何数值缩放**（§1.5 硬红线）——保证 EHP 上限侧是玩家"选择变轻松"，而非系统偷偷补偿。
3. **调参杠杆优先级**（若实测发现 SSR 让内容过于轻松，按此顺序下调，不要动稀有度总乘子）：
   `hp 权重 1.0 → 0.8`  ➜  `defense 权重 0.7 → 0.5`  ➜  最后才考虑动 `rarity_milli`。
   （动总乘子会同时影响五维，牵一发动全身；动单维权重影响面可控。）

## §4 抽取经济（Pull Economy）

### 4.1 双货币

| 货币 | 代号 | 定位 | 获取方式 |
|---|---|---|---|
| **共鸣尘** Resonance Dust | `dust` | 常规流水货币 | 击杀 / 探索 / 宝箱（**游玩即得**） |
| **星辉** Astral Light | `astral` | 稀缺里程碑货币 | Boss 首杀 / 里程碑 / 成就 / 隐藏浮岛（**成就即得**） |

> **⚠ C4 裁决（待用户拍板）**：任务书原始描述中"星辉"为 premium（付费）货币。本方案 **v1 建议不接入真实货币支付**——买断制 Steam 单机放内购会引发玩家反弹，且与概念 §1「Solo 精品」定位冲突。
> 保留的是双货币的**稀缺性结构**（服务节奏设计：日常流水 vs 里程碑奖赏），而非付费墙。数据 schema 预留 `astral` 字段，未来若做资料片再评估，**默认关闭**。见 §8 待批项 1。

**不设兑换（刻意决策）**：两种货币**不可互相兑换**。任何固定兑换率都会立刻产生"最优兑换路径"这一主导策略（玩家算出该囤哪种），并把两种货币压缩成一种。双币的意义在于**节奏区分**，不是套利空间。唯一的"转换"路径是重复角色 → 共鸣尘（§4.5）。

### 4.2 获取速率与节奏（继承 meta-progression「无 grind」原则）

| 来源 | 货币 | 数量 | 类别 |
|---|---|---|---|
| 普通敌击杀 | dust | +2 | 刷怪（次要） |
| 精英敌击杀 | dust | +8 | 刷怪（次要） |
| 探索宝箱 | dust | +40 | **发现（主导）** |
| 里程碑 | dust | +150 | **发现（主导）** |
| 隐藏浮岛发现 | dust | +250 | **发现（主导）** |
| Boss 首杀 | astral | +5 | 里程碑 |
| 章节里程碑 | astral | +2 | 里程碑 |
| Steam 成就 | astral | +1 | 成就 |

**配比校验（守 C2 裁决）**：单次 20–40 分钟 session 约得 `30×2 + 2×8 + 3×40 + 150 ≈ 346` dust，其中**刷怪仅占 ~22%**（76/346），**探索与里程碑占 ~78%**。 → 继承 `meta-progression.md §②`「技能点来自发现，非刷怪」的精神。**刷怪不是有效的抽卡货币来源**，杜绝 grind wall。

**v1 全周期总量**：约 **45–60 抽**（≈ 40 抽来自 dust + 15 抽来自 astral）。配合 §4.4 新手保底，玩家在 v1 内**必得 1 个 SSR，约 50% 概率得第 2 个**，并可收齐大部分 8 人花名册。

### 4.3 单抽 / 十连规则（⚠ 主导策略防守）

| 方式 | 成本 | 保底 |
|---|---|---|
| **单抽** | `160 dust` **或** `1 astral` | 走全局保底计数器 |
| **十连** | `1600 dust` **或** `10 astral` | 走全局保底计数器（**无额外折扣、无额外保底**） |

**这是本节最重要的设计决策**：

> 绝大多数抽卡游戏中，十连享有折扣或独占保底 → **十连严格优于单抽** → 单抽沦为"新手陷阱"（newbie trap），一个专门惩罚不懂行玩家的主导策略。**本作明确拒绝这一设计。**

做法：**保底计数器 `pity_sr` / `pity_ssr` 是跨抽次的全局连续计数器**，不按"每发十连内部"重置。

由此：
- ✅ **十连与 10 次单抽的期望产出、方差、保底触发时机完全相同**（可断言，见 `AC-GACHA-02`）。
- ✅ 任务书要求的「十连给保底最低档以上 1 件」**依然成立**——因为 `PITY_SR_HARD = 10` 的全局计数器保证**任意连续 10 抽内必出 SR+**，其中自然包含每一发十连。
- ✅ 十连的价值回归为**纯粹的便利**（一次点完 + 一段更长的召唤演出），玩家按心情选择 → **直接服务 Autonomy**。

### 4.4 新手保护（防沉没成本 + 建立心流锚点）

| 机制 | 规则 | 设计意图 |
|---|---|---|
| **首抽半价** | 前 **20 抽**成本减半（`80 dust` / 单抽） | 降低首次尝试门槛，让玩家先体验系统再决定投入 |
| **第 10 抽必出 SSR** | 累计第 10 抽**强制**产出一个 SSR（`novice_bonus_used` 标记，永久一次性） | **最关键的一条**。玩家在开局约 1–2 小时内**保证**获得一位星级角色作为"锚点角色"，立即建立 Relatedness 与 Competence，而不是在 46 抽的期望值里空转 |
| **无 FOMO** | 无限时卡池、无每日任务、无体力值、无登录奖励 | 主动放弃 Submission 美学（§1.3）——买断制单机不需要习惯性重复 |

> 沉没成本防护的本质：**让玩家任何时刻停手都不觉得亏**。保底计数器**全程可见**（HUD 显示"距星级保底还剩 N 抽"），把不可知的随机变成可规划的进度——这也是把 Gambling 心理转化为 Achievement 心理的关键。

### 4.5 重复角色处理（⚠ 防数值通胀）

抽到已拥有角色时：

1. **绝不叠加数值**。不做"同角色 ×N 提升星级/突破"。
   > 理由：一旦重复能提升数值，数值上限就变成**抽取次数的函数**而非设计常量，`§3.7` 的全部边界失效，P1/P2 守卫全部作废；同时这正是 F2P 手游的付费深渊结构，与买断制承诺冲突。
2. **转化为共鸣尘返还**：

   | 档 | 返还 dust | 折合抽数 |
   |---|---|---|
   | 尘 N | 40 | 0.25 |
   | 铁 R | 120 | 0.75 |
   | 辉 SR | 400 | 2.5 |
   | 星 SSR | 1200 | 7.5 |

3. **roll 重掷权（重复的真正价值）**：每次抽到重复角色，获得该角色的**一次 roll 重掷机会**。重掷后系统**同时展示新旧两组 roll，由玩家显式选择保留哪一组**。
   > 这给了重复一个有意义、有决策感的用途，**却不抬高数值上限**（重掷范围仍是 `[950,1050]`）。玩家追求的是"把我心爱的角色调到极品 roll"，是**打磨**而非**通胀**。这是本系统里最能产生长期依恋的机制。

## §5 数据模型草案（交付工程）

> 本节为 **schema 草案**，非实现。字段风格对齐现有 `game/src/ai/enemy_definition.gd`（`@export` + StringName id + 整数数值 + 注释标注真理源）。

### 5.1 核心分层原则（对齐 ADR-002 / ADR-004 纪律）

三层严格分离，**这是本系统能通过现有 CI 门禁的前提**：

| 层 | 载体 | 内容 | 是否入档 |
|---|---|---|---|
| **规则常量** | `GameConstants` | 概率 bp、保底阈值、稀有度乘区、维度权重、roll 范围、成本 | ❌ **绝不入档** |
| **静态定义** | `CharacterDefinition`（`.tres` 资产） | 角色 id / 职阶 / 稀有度 / 五维基线 / 美术引用 / 文案 | ❌ 不入档（存 id 引用即可） |
| **实例状态** | `OwnedCharacter`（存档数据） | 已拥有角色的 **roll 值**、获取时间 | ✅ **必须入档** |

> ⚠ 对 `SaveModel.FORBIDDEN_KEYS` 的**必要扩展**（否则 `test_save_no_constants.gd` 无法守住本系统）：
> 追加 `"rarity_rates", "rarity_bp", "rarity_mult", "stat_weights", "pity_soft", "pity_hard", "pity_ssr_soft", "pity_ssr_hard", "pity_sr_hard", "roll_min", "roll_max", "pull_cost"`。
> 注意区分：`pity_ssr`（当前计数，**是状态，允许入档**）vs `pity_ssr_hard`（阈值 90，**是常量，禁止入档**）。**这两个名字极易混淆，是本系统最可能出现的存档污染点。**

| 字段 | 类型 | 默认 | 说明 |

| `display_name` | `String` | `""` | 显示名（如「星·断空剑主」） |
| `archetype` | `StringName` | `&"BLADE"` | `BLADE` / `BULWARK` / `WINDCHASER` / `RESONANT` |
| `rarity` | `int` (enum) | `0` | `0=N / 1=R / 2=SR / 3=SSR` |
| `base_hp` | `int` | `95` | 五维基线（职阶基线 ±3） |
| `base_attack` | `int` | `118` | 同上 |
| `base_defense` | `int` | `90` | 同上 |
| `base_move_speed` | `int` | `102` | 同上 |
| `base_resonance_affinity` | `int` | `95` | 同上 |
| `model_scene` | `PackedScene` | `null` | 角色模型（**共用同一骨骼/动画集**，见 §8 待批项 2） |

> 扫描 `.tres` 目录全量断言 → 任何新角色若数值超预算，CI 直接红。**这把"不许数值通胀"从口头纪律变成了门禁。**

### 5.3 `CharacterStats`（运行时值对象 · 不入档）

由 `CharacterDefinition` + `rarity` + `roll` 经 §3.5 公式计算得出的**最终五维**。纯逻辑、可独立实例化（对齐 ADR-002 对 `resonance_model.gd` 的处理方式，便于无场景树单测）。

建议落点：`game/src/meta/character_stats.gd`（纯逻辑，`RefCounted`）。
其中数值解算函数应为 **static、无副作用**，使 `AC-GACHA-03` 可直接对公式做表驱动断言。

### 5.4 `Roster` Autoload（花名册）

**Autoload 准入红线校验（`architecture.md §4.3`：须同时满足三条）**

| 红线 | 是否满足 | 论据 |

**职责边界（严格限定，防单例滑坡）**

| 职责 | 说明 |

| 持有货币余额 | `dust` / `astral` |
| **唯一的抽卡入口** | `try_pull(count)` —— 内部完成扣费 → 判定稀有度 → 掷 roll → 更新计数器 → 广播事件 |
| **唯一的出战切换入口** | `set_active(character_id)` |
| 计算出战角色最终五维 | 委托 `CharacterStats`（自身不含公式） |

**强制约束（照搬 ADR-002 的成功模式）**
1. **无 setter**：`dust` / `astral` / `pity_*` 一律私有 + 只读访问器；外部只能经 `try_pull()` 等方法改动。这使"绕过扣费"与"绕过保底"在物理上不可能。
2. **不持有规则**：概率、阈值、乘区、权重全部读 `GameConstants`。改平衡 = 改 GDD + 改 `GameConstants`，`Roster` 代码不动。
3. **不持有第二份角色数值**：HUD 与战斗一律经 `Roster` 查询，禁止缓存副本（同 ADR-002 对 HUD 缓存的封堵）。
4. **随机源可注入**：`try_pull()` 接受可选 seed / RNG 注入，使 `AC-GACHA-01` 的 10 万次采样可复现。**这一条是概率可测试性的前提，请工程务必保留。**
5. 暴露 `reset_for_test()` 供 gdUnit4 `before_test()` 调用（同 `ResonancePool`）。

### 5.5 存档 schema 扩展（ADR-004 · 需 `SCHEMA_VERSION` 1 → 2 + 迁移器）

在 `SaveModel.new_save()` 顶层追加两个键：

```
"roster": {
    "owned": [
        {"id": "aster_voidblade", "roll_atk": 995, "roll_def": 1000, "roll_aff": 1000, "acquired_at": 0}
    ],
    "active_id": "aster_voidblade",
    "pity_ssr": 0,
    "pity_sr": 0,
    "total_pulls": 0,
    "novice_bonus_used": false
},
"currency": { "dust": 0, "astral": 0 }
```

**`clamp_fields()` 需追加的钳制**（明文 JSON 可被玩家手改，ADR-004 决策 5：不阻止作弊，但绝不允许非法值让游戏进入不一致状态）：

| 字段 | 钳制规则 |
|---|---|
| `roll_atk/def/aff` | `clampi(v, 950, 1050)`，且**须为 5 的倍数**（否则吸附到最近档位） |
| `pity_ssr` | `clampi(v, 0, GameConstants.PITY_SSR_HARD)` |
| `pity_sr` | `clampi(v, 0, GameConstants.PITY_SR_HARD)` |
| `dust` / `astral` / `total_pulls` | `maxi(0, v)` |
| `active_id` | 若不在 `owned` 列表内 → 回落到列表首个；`owned` 为空 → 回落 `""`（触发默认角色，见 §6.1） |
| `owned[].id` | 若在 `CharacterDefinition` 资产库中不存在（如删角色后读旧档）→ **静默丢弃该条**，不拒绝整档 |

> **迁移器 `migrate_1_to_2()`**：老存档（v1，无抽卡）读入时，注入空 `roster` + 零 `currency`，`active_id = ""`。**老存档必须能正常读取**，这是 `AC-GACHA-04` 的断言项之一。

## §6 与现有系统的接口

### 6.1 → S1 `PlayerCombat`（出战数值注入）

**现状**：`player_combat.gd` 中 `max_hp` / `hp` 直接取 `GameConstants.PLAYER_MAX_HP`（=100），`take_damage()` 直接扣减。

**接入方式（最小侵入）**

| 接口 | 改动 | 说明 |
|---|---|---|
| `apply_character(stats)` | **新增方法** | 在 `initialize()` 末尾调用；设 `max_hp = stats.hp`、`hp = max_hp`，缓存 atk/def/aff |
| `take_damage(amount)` | **改一行** | 入口处先 `amount = amount * 100 / stats.defense`，其余逻辑（无敌判定、事件广播）**完全不变** |
| 伤害输出 | 命中结算处 | `dmg = 招式基础伤害 * stats.attack / 100` |
| 终结技伤害 | 终结技结算处 | `dmg = 基础 * clampi(stats.affinity, 80, 200) / 100` |
| 移动 | S2 移动系统 | `实际移速 = 基准 * stats.move_speed / 100` |

**🔑 兼容性硬要求（保护现有 60+ 测试）**

> `GameConstants.PLAYER_MAX_HP = 100` **必须保留**，其语义从"玩家血量"变更为 **"N 档基线参考值"**。
> `PlayerCombat` 在 **`Roster.active_id` 为空时必须回落到 `PLAYER_MAX_HP` 与全 100 标量**（等价于当前行为）。
>
> 这使抽卡系统成为一个**可完全关闭的 feature flag**：未启用时全部既有战斗测试、关卡调校、伤害数值**逐帧一致、零回归**。这条不是可选的整洁度，是让本大系统能安全并入 Phase 5 已完成工作的**唯一前提**。

**不得触碰的边界**：`CANCEL_WINDOW` / `PARRY_WINDOW` / `DASH_IFRAMES` / `PARRY_SLOWMO_*` —— **任何角色、任何稀有度均不得修改任何窗口帧数**。窗口是 P1 的技巧表达基准，一旦可被抽卡影响，"抽到好卡 = 操作变简单"，胜任感归因彻底崩塌。**这条与 §1.5 的"敌人不缩放"是同一枚硬币的两面。**

### 6.2 ↔ S3 共鸣池联动（P4 共鸣统一）

- **成本恒定**：`GATE_COST = 30` / `FINISHER_COST = 40` **不受任何角色影响**。互斥张力的强度 = 成本 / 收入，两者都不动，P4 的机会成本结构**逐点保持不变**。
- **产出差异化**：仅终结技伤害随 `affinity` 变化（`×0.88 ~ ×1.93`）。
- 由此得到的体验：**"花掉同样的 40 点，谐律角色打得更狠"**——差异体现在**支出的回报率**，而非**收入的速率**。这让共鸣亲和成为一个有意义的角色特质，同时**一点也没有削弱"开门 vs 终结技"的两难**。

**⚠ 需监控的次生主导策略**：谐律角色抬高了终结技的边际价值，玩家可能系统性囤池打终结技、推迟开门。
**可测量红线**：若 playtest 显示使用谐律角色时**闸门使用率相对基准下降 > 40%**，判定为主导策略，处置 = 下调 `affinity → 终结技伤害` 的斜率（例如从 1:1 改为 1:0.6），**不要动共鸣池常量**。

### 6.3 🔴 裁决：击杀 +15（ADR-002）**不受**共鸣亲和影响

> **`ResonancePool.add(GameConstants.GAIN_KILL, ...)` 中的 `15` 保持为常量，绝不乘以角色亲和系数。**
> 命中 +1 / 完美格 +5 / 节点 +10 / 脱战 +2/s 同理，**全部不受影响**。

四条论据：

1. **P4 支柱会当场失效（设计正确性）**
   ADR-002 开宗明义：「只要存在第二份池数值，P4 就不成立」。虽然乘系数不是"第二份数值"，但它制造了**第二份规则**——同样的击杀在不同角色下产生不同收入，"共鸣是统一的元技能"这一支柱陈述不再为真。
   更致命的是**互斥张力的塌缩**：亲和 193 的角色收入接近翻倍，等于把 `GATE_COST + FINISHER_COST = 70` 的两难压缩成"两个都负担得起"。`concept §1 P4` 的验证条款「不存在只点战斗不点解谜的主导策略」**直接失守**。

2. **违反 ADR-002 决策 2（架构正确性）**
   「常量不落地在池里……`ResonancePool` 只持有当前值，不持有规则」。若 `add()` 内部读取角色亲和，池就开始持有规则，且引入了对 `Roster` 的反向依赖——**S3 是 systems-index 认定的根资源（无前置依赖）**，让它依赖 S9 会**产生依赖环**（S9 → S1 → S3 → S9），破坏 `systems-index §1` 的实现顺序基石。

3. **调用点乘算会绕开唯一写入路径（工程正确性）**
   若改在调用侧写 `ResonancePool.add(15 * aff / 100, ...)`，则"增益值"这一规则就散落到每一个调用点，ADR-002 苦心构建的"唯一入口 + 不可绕过"当场瓦解，且 `test_constants_match_gdd.gd` 无法再守住 `GAIN_KILL`。

4. **玩家心理上也更好（体验正确性）**
   收入恒定 = **所有角色的共鸣节奏一致**，玩家换角色时不需要重新学习"我大概几个杀能攒出一发终结技"。这守住了概念 §3 的防认知过载原则。差异放在"这一发有多爽"上，**感知强度更高、学习成本更低**。

**✅ 结论**：共鸣亲和 **只出现在终结技伤害计算中**，`ResonancePool` 的代码与常量**一行都不需要改**。S3 保持根资源地位，无新增依赖。

### 6.4 → S6 HUD / UX

- **战斗中 HUD：零新增元素**（守概念 §3 防认知过载）。出战角色的数值差异**已经体现在现有血条与共鸣条上**，不需要新控件。
- **新增界面仅两处，均在非战斗上下文**：
  1. **星轨召唤**（神龛/据点）：抽卡入口 + 保底进度条 + 召唤演出。
  2. **花名册**（神龛/关卡前）：角色列表、五维对比、出战切换、`lore_text` 图鉴。
- 稀有度呈现遵守 §2.1 的 Token 与强制非色编码；界面底色 `UI_BG`。

### 6.5 → S8 神龛 / 存档

- **出战角色切换点 = 神龛**（与技能树应用点一致，`meta-progression §②`），语义统一：**神龛是唯一的"重新配置自己"的地方**。
- 花名册、货币、保底计数器随神龛存档写盘（§5.5）。
- **抽卡货币与技能点严格隔离、不可互换**——技能点仍只来自"发现/里程碑"，S8 的经济纪律不被污染。

### 6.6 → S7 叙事

- 每个 `CharacterDefinition` 可挂 `echo_id`，首次获得该角色时解锁一段残响片段。
- 这让抽卡产出**同时是叙事产出**，直接服务 P3「精美即叙事」与 §1.4 的 Relatedness 论证。

## §8 待批准项、已知风险与开放问题

### 🔴 待用户拍板（阻塞落地）

**待批项 1 · 商业模式：是否接入真实货币内购？**
任务书将"星辉"定义为付费（premium）货币。本作是 **Steam 买断制单机**，引入内购会引发玩家强烈反弹，且与「Solo 精品」定位冲突。
- **推荐（A）**：两种货币均通过游玩获取，保留稀缺性结构，`astral` 预留字段但不接支付。
- 备选（B）：接入 IAP。若选此项，需追加：退款政策、概率公示合规（中国大陆/韩国等地强制公示抽卡概率）、未成年人保护、Steam 内购接入工作量。
- **我的建议：A。** 本文档 §4 已按 A 撰写；若改选 B，§4.1 与 §4.2 需重写。

**待批项 2 · 美术生产成本：v1 角色池规模**
P3「精美即叙事」要求每个角色达到 stylized PBR 3D 精品标准。这是本系统**最大的项目风险**——角色美术量可能超过项目其余全部美术量之和。
- **推荐（A）**：v1 **8 个角色**（尘 2 / 铁 2 / 辉 2 / 星 2），**全部共用同一套骨骼与动画集**，差异化仅靠模型/材质/配色/特效。§4.2 的 45–60 抽经济即按此校准。
- 备选（B）：16–20 个角色（更接近典型抽卡体量，但美术工作量 ×2~2.5，**极可能压垮 Solo 排期**）。
- **我的建议：A**，并请林绘澄评估「共用骨骼下 8 个角色的辨识度是否足够」。

**待批项 3 · 概念文档范围变更（C1 / C2）**
需要正式修订两处已拍板文档：

### 开放问题

- 角色是否应有**专属动词变体**（如风追的荡有二段）？→ 会显著增强 Expression，但直接冲击 P1 的统一取消语言与美术成本。**建议 v1 不做**，留待资料片。
- 是否允许**队伍编成**（多角色轮换出战）？→ 会大幅增加战斗复杂度与认知负担。**建议 v1 明确不做**（单角色出战）。
- 花名册收齐是否给 **Steam 成就 / Achiever 奖励**？→ 建议做，成本极低，直接服务概念 §4 的 Achiever 覆盖。
- N 档角色在后期是否彻底失去意义？→ 可考虑"挑战模式：用 N 卡通关"作为 Killer 型玩家的自我加难，把弱势转为内容。
