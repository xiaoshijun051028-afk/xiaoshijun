# ADR-001 · 引擎选型与版本钉定：Godot 4.7.1

> 编号 ADR-001 ｜ 日期 2026-08-08 ｜ 作者 程基岩 ｜ 评审 Solo
> 关联：`architecture.md` §1 / §12.1 ｜ 上游：概念文档 v0.2、美术圣经 v0.1

## 状态

**已接受（Accepted）** —— 引擎选型由主理人在 Phase 1 预先钉定为 Godot 4；本 ADR 的实质决策是**具体版本分支的钉定与升级策略**。

## 背景

概念文档 v0.2 与美术圣经均已写明「Godot 4（3D）/ PC · Steam」，引擎品类无争议。但"Godot 4"不是一个可施工的版本号——Godot 采用 `major.minor.patch`，不同 minor 分支之间的能力与支持级别差异巨大，而本项目的美术圣经依赖若干**有明确引入版本**的能力：

- `CompositorEffect`（美术圣经 §3.3 / §8.1 明确点名，标注"4.3+"）
- SDFGI / VolumetricFog / GPUParticles3D（标注"Godot 4 内置"）
- 全项目 Fresnel Rim 描边（§4.3）——干净外描边需要模板缓冲
- 可访问性基线 Standard（§9.4）——需要屏幕阅读器支持

同时 GDD 提出了以帧计的手感常量（`CANCEL_WINDOW=8f` 等），需要引擎具备稳定的固定时间步 + 物理插值能力，否则高刷显示器上无法保证一致手感。

因此必须回答：**钉哪个分支？何时升级？**

### 版本现状核验（2026-08-08，来源 godotengine.org 发布页与官方 release policy）

| 分支 | 发布日期 | 支持级别 |
|---|---|---|
| 4.8 (master) | Q4 2026 预计 | 开发中，不可用于生产 |
| **4.7**（4.7.1 于 2026-07-14；4.7.2-rc1 于 08-03） | 2026-06-18 | 完整支持（bug + 安全 + 平台） |
| 4.6（4.6.3 于 2026-05-20） | 2026-01-26 | 完整支持 |
| 4.5 | 2025-09-15 | 仅安全与平台修复 |
| 4.4 及更早 | — | 已停止支持 |

### 能力引入版本核验

| 能力 | 引入版本 | 本项目需求来源 |
|---|---|---|
| SDFGI / VolumetricFog / GPUParticles3D / 自定义 Sky Shader | 4.0 | 美术 §3.1 §3.2 §8 |
| `CompositorEffect` | **4.3** | 美术 §3.3 §8.1 |

| HDR 输出；`AreaLight3D`；键鼠设备 ID；`Control.offset_transform_*`；`tween_await()` | **4.7** | 美术 §3.3 Glow；GDD S6 双设备仲裁与 HUD 动效 |

## 决策

1. **钉定 `Godot 4.7.1-stable`，标准构建（非 .NET / 非 Mono）**。
2. **渲染方法 `Forward+`**；Windows 导出图形 API 用 D3D12，保留 Vulkan 作为命令行回退。
3. **语言 GDScript，零 C#**；如出现真实 CPU 瓶颈，走 GDExtension 局部替换，不做全项目语言迁移。
4. **版本升级策略**：
   - **patch 升级（4.7.1 → 4.7.2 …）**：默认采纳，跑一遍 CI + 3 个基准场景即可合入。
   - **minor 升级（→ 4.8）**：需一个独立评估 spike（新分支 + 全测试 + 性能基线比对），并记录为新 ADR。
   - **Beta 里程碑后冻结**：进入 Beta 即锁死 minor 分支，只接受 patch，避免临近发布的引擎变更风险。
5. **CI 与本地引擎版本由 `GODOT_VERSION` 单点声明**（CI env + README），杜绝"本地能跑 CI 不能跑"。

### 为什么是 4.7 而不是 4.6

4.6 完全够用（CompositorEffect、stencil、Jolt、SSR 重写都已就位），但 4.7 带来四项**直接命中本项目已写死需求**的能力，且其中两项能消除本来要自己写的代码：

- **键鼠设备 ID** → GDD S6 §⑥「双设备同时输入，最近输入设备优先」从"手工推断"变成"读设备 ID"；
- **`Control.offset_transform_*`** → HUD 动画不再需要额外包一层 Control 绕开 Container 重排；
- **`AreaLight3D`** → 神龛/共鸣节点的发光面从"自发光 + 依赖 SDFGI 弹跳"变成真实面光源，画质更好且**降低对 SDFGI 高档位的依赖**（性能利好）；
- **HDR 输出** → 美术圣经 §3.3 追求的高阈值 Glow 能量感在 HDR 显示器上真正兑现。

且 4.7 已有一个维护版（4.7.1）、第二个在 RC，早期缺陷已收敛一轮。项目此刻才进入 Phase 4 预制作，是承担这点新鲜度风险的最佳时点——越往后改引擎越贵。

### 为什么不是 Unity / Unreal 5

已在 Phase 1 由主理人钉定，此处仅补技术论证备查：

- **Unity**：Godot 场景/节点模型在 Solo 规模迭代更快；无运行时收费与许可政策不确定性；GDScript 改完即生效对"手感靠反复调"是核心生产力。Unity 的 DOTS / HDRP 优势（大规模实体、写实光照）在本项目用不上。
- **Unreal 5**：Nanite/Lumen 面向写实高模，与本项目 stylized 方向（美术 §4.3 明确"避免高频噪点法线"、"大块明暗 + 干净高光"）相反；GAS 对单人 6 动词是过度工程；C++/Blueprint 双轨 + 长构建时间对 Solo 是持续税负。
- **决定性因素**：本项目瓶颈是**手感迭代速度**（支柱 P1，取消窗口靠反复试），不是渲染上限。秒级迭代 > 理论画质天花板。

## 后果

**正面**

- 美术圣经点名的全部渲染能力**零第三方依赖**即可实现，附录声称的"PC·Steam 性能充裕"经核验成立。
- 4.6 起 Jolt 为 3D 默认物理，无需引入 godot-jolt GDExtension，依赖面进一步收窄。
- 4.5+ 的 AccessKit 让可访问性 Standard 基线（美术 §9.4）有原生支撑，而非自研。
- 标准构建导出体积小、无 .NET 运行时分发问题，Steam 上架流程简单。
- 处于完整支持分支，遇到引擎 bug 有官方修复通道。

**负面 / 成本**

- 4.7 发布仅约 2 个月，相对 4.6 社区踩坑资料少；遇到冷门问题可能需要自己读引擎源码。**缓解**：4.7.1 已是维护版；保留"降级到 4.6.3"的逃生门——本项目未使用任何 4.7 独占的**不可替代**能力（四项增量都有 4.6 下的替代实现路径，只是更麻烦）。
- GDScript 无编译期强校验，重构风险高于 C#。**缓解**：强制静态类型标注 + gdlint + 单测门禁（`architecture.md` §11.4）。
- 4.8 预计 Q4 2026 发布，若届时项目仍在制作期，会面临"升不升"的判断。**缓解**：已在决策 4 中定义升级策略与冻结点。

**风险登记**

- **RISK-ENG-1**：4.7 的 SDFGI / VolumetricFog / CompositorEffect 在官方 4.7 发布说明中**未见专门更新条目**，本文按 4.3–4.6 既有行为规划。若 Phase 4 实测行为有变，需修订 `architecture.md` §6。检测手段：S0 阶段的渲染管线冒烟场景。
