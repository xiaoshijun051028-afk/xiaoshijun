# ADR-002 · 共鸣池实现为 Autoload 单例（唯一权威 / Single Source of Truth）

> 编号 ADR-002 ｜ 日期 2026-08-08 ｜ 作者 程基岩 ｜ 评审 Solo
> 关联：`architecture.md` §4.2 / §4.3 / §5 ｜ 上游：GDD S3 `resonance.md`、systems-index §2 §3

## 状态

**已接受（Accepted）**

## 背景

共鸣池（S3）是整个设计的**支柱级机制**，不是普通资源条：

- 概念文档支柱 **P4「共鸣统一」**：共鸣是同时驱动解谜闸门与战斗终结技的元技能，**二者共享同一能量池**。
- 该支柱的**验证方式就是互斥性**：「共鸣池同时承担开门与终结技且互斥消耗——不存在只点战斗不点解谜的主导策略」。
- systems-index §1 把 S3 列为**根资源（无前置依赖）**，被 S1 / S5 / S7 / S8 四个系统消费，实现顺序排第一。

工程含义非常硬：**只要存在第二份池数值，P4 就不成立，防主导策略的设计目标当场失效**。这不是代码整洁度问题，是设计正确性问题。

典型的失效方式（都必须被架构阻断）：

1. HUD 为了显示流畅缓存了一份 `resonance` 副本，某次事件漏订阅 → 显示与实际不符 → 玩家以为能放终结技却灰着。
2. 战斗系统与解谜系统各持一个引用，某处直接写字段而非走扣费方法 → 绕过互斥。
3. 存档把 `MAX=100` 一起写进去 → 后续调平衡改成 120，老存档读回 100 → 出现第二真相源。
4. 同一帧内既触发开门又触发终结技 → 双花（GDD S3 §⑥ 明确要求裁决优先级）。

同时还要满足：跨场景存活（换岛不丢池值）、随神龛存档、被 HUD 实时观察。

### 备选方案

- **A. Autoload 单例**（全局节点，`/root/ResonancePool`）
- **B. 静态类 / 纯 GDScript static 变量**
- **C. 挂在 Player 场景下的组件节点**
- **D. `Resource` 资源实例共享（`.tres` 全局引用）**
- **E. 事件溯源（只存事件流，值靠回放推导）**

## 决策

**采用 A：Autoload 单例 `ResonancePool`**，并附加四条强制约束：

### 1. 封装写入路径——外部无法直接改值

```gdscript
# autoloads/resonance_pool.gd  (Autoload 名: ResonancePool)
extends Node

var _current: int = GameConstants.RESONANCE_INITIAL   # 私有，下划线前缀

## 只读访问器：外部可读不可写
var current: int:
    get: return _current

func can_afford(cost: int) -> bool:
    return _current >= cost

## 唯一的扣费入口。返回是否成功——调用方必须检查。
func try_spend(cost: int, reason: StringName) -> bool:
    if _current < cost:
        EventBus.resonance_spend_rejected.emit(cost, reason)
        return false
    _set_value(_current - cost)
    return true

## 唯一的增益入口，自动钳制上限（GDD S3 §⑥ 溢出丢弃）
func add(amount: int, source: StringName) -> void:
    _set_value(mini(_current + amount, GameConstants.RESONANCE_MAX))

func _set_value(v: int) -> void:
    var old := _current
    _current = clampi(v, 0, GameConstants.RESONANCE_MAX)
    if _current != old:
        EventBus.resonance_changed.emit(_current, old)
```

**没有 setter**。任何系统想改池，只能经 `try_spend()` / `add()`，上限钳制与事件广播因此**不可能被绕过**。

### 2. 常量不落地在池里

`MAX / INITIAL / GATE_COST / FINISHER_COST / 各增益值` 全部从 `GameConstants` 读取（其值源自 systems-index §2）。`ResonancePool` **只持有当前值**，不持有规则。改平衡 = 改 GDD + 改 `GameConstants`，池代码不动。

### 3. 同帧双消耗裁决（GDD S3 §⑥）

GDD 规定「同一帧既开门又终结技 → 优先玩家主动输入（终结技），闸门排队」。实现为**同一物理 tick 内的顺序保证**：

- 战斗 FSM 在 `_physics_process` 中**先于**世界交互系统执行（通过 `process_priority` 固定顺序）；
- 闸门开启请求若在本 tick 内失败，进入 `_pending_gate` 队列，下一 tick 重试一次即丢弃并提示。

因为 `try_spend()` 是同步返回的，不存在"两个请求都以为自己成功"的竞态。

### 4. 存档只存当前值

`save.resonance.current` 一个字段。读档时 `_set_value(loaded)` 并再次钳制（防篡改存档写入 999）。

## 后果

**正面**

- **P4 支柱在架构层被强制成立**：物理上只有一份数值、只有一个写入路径，互斥性不依赖任何人的自律。
- GDD S3 §⑦ 四条验收标准可直接单测，且**不需要场景树**（纯逻辑，毫秒级）：
  - 池上限严格 100 不溢出 → `add(999)` 后断言 `current == 100`
  - 终结技恰扣 40、闸门恰扣 30
  - **池=35 时可开门不可终结技**（互斥核心断言）
  - 节点 5s cd 内不二次增益
- HUD / VFX / 音频通过 `EventBus.resonance_changed` 被动更新，无需轮询，也无法产生副本。
- 跨场景天然存活，换岛不需要任何搬运代码。

**负面 / 成本**

- Autoload 是全局状态，**测试需隔离**。对策：`ResonancePool` 暴露 `reset_for_test()`，gdUnit4 的 `before_test()` 中调用；纯逻辑部分抽到 `src/core/resonance_model.gd` 可独立实例化，Autoload 只是它的一个全局宿主。
- 单例有滑坡风险（"什么都塞 Autoload"）。对策：`architecture.md` §4.3 定义了 Autoload 准入红线（全局唯一 + 跨场景存活 + ≥3 系统消费），S3 三条全中。
- 全局信号让"谁改了池"在调试时不直观。对策：`add()` / `try_spend()` 均带 `source`/`reason` 参数并写入 `DebugOverlay` 环形日志，可回看最近 N 次变更来源。

**被否方案与理由**

| 方案 | 否决理由 |
|---|---|
| **B. 静态类** | GDScript 静态成员无法发信号、不参与场景树生命周期、`reset` 与存档时机难管；调试器里也看不见。 |
| **C. Player 下的组件** | 致命：S5 闸门、S7 残响节点在**没有玩家实例的上下文**（如关卡校验工具、纯逻辑测试）也要查询池；且玩家死亡/重生会重建节点，池值生命周期错位。 |
| **D. 共享 `Resource`** | Godot 中 `.tres` 在编辑器里被修改会**写回磁盘**，运行时改值可能污染源资产；且资源可被多处 `duplicate()`，恰恰破坏"唯一"。 |
| **E. 事件溯源** | 对 Solo 项目是显著过度工程；每次查询都要回放，`_physics_process` 内不可接受。 |

## 备注

- 这条 ADR 与 **ADR-004（存档格式）** 强耦合：存档**不得**写入池的上限/成本常量，否则老存档会带回旧规则，制造第二真相源。已在 ADR-004 与 `architecture.md` §10.2 明确。
- 同一"唯一权威"模式也应用于 `GameConstants`（常量）与 `ColorTokens`（语义色，见 `architecture.md` §9）——三者构成本项目的三个单一真相源。`ColorTokens` 的取值权威为 **`design/color-tokens.md` v1.0**（**CONCERN-A 已裁决：color-tokens.md v1.0**，2026-08-08）；退役 hex `#2BB6A8` / `#F4B740` 禁止作为活值出现。
- 待裁决缺口：GDD S3 §⑧ 开放问题「共鸣溢出是否转化为分数」「双消耗优先级是否做成设置项」——当前实现按 GDD §⑥ 硬编码为"溢出丢弃 + 终结技优先"，若要改为可配置需新 ADR。
