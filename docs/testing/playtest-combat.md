## Part A · S1-01 SPIKE-3 手感原型

**目标**：兑现支柱 P1「流动即正义」——斩/闪/跃三动词 + ≤8 帧取消窗，连段手感顺滑、中断感可接受。

### A.1 最小场景准备
- 载入最小战斗场景（1 个木桩/假人敌人即可，无需完整关卡）。
- 确认输入：斩（轻攻）、闪（位移+无敌）、跃（突进）三动词可用，收招期有取消窗提示（调试 HUD 可显 `cancellable` 状态）。

### A.2 客观旁证（已在前述集成测试覆盖，此处只做体验确认）
- [ ] 斩→闪取消接得上，无「卡顿 1 拍」感。
- [ ] 闪→斩反击接得上。
- [ ] 跃→闪→斩三连在 ≤8 帧窗口内成链。

### A.3 主观手感核对（试玩人逐项打 √ / 备注）
由 **程基岩 + 主理人 + 严守真** 三人各试玩一轮，记录中断感：

| 维度 | 期望 | 你的感受（√/× + 备注） |
|---|---|---|
| 响应延迟 | 按键到动作起手 ≤ 手感阈值 |  |
| 取消窗宽度 | 8 帧（~133ms）体感「刚好能接」不「宽到无脑」 |  |
| 命中反馈 | hit-stop 60–90ms + 轻微震屏，有「砸中」感 |  |
| 连段流动 | 一套多段连招中途不「断气」 |  |
| 输入容错 | 略早/略晚按不丢输入、不误触发 |  |
| 总体中断感 | 可接受（不令人烦躁） |  |

### A.4 不达标处理（数据驱动，改 `.tres` 不改代码）
- 取消窗太窄/太宽 → 调 `CANCEL_WINDOW`（架构 §3 时间基准），纯数据。
- 起手太慢 → 调对应 `VerbDefinition.tres` 的起手/收招帧数。
- 反馈太弱 → 调 hit-stop 时长 / 震屏幅度（`CameraRig`/全局，非 `_process` 改状态）。
- 改完回到 **0 客观门** 重跑，再回来重测 A.3。

## Part B · S1-06 连段中断率 <5%（人工统计）

**目标**：20 名玩家原型测试，连段中断率 <5%。超标则回 SPIKE-3 / verb 帧数调参。

### B.1 定义（统一口径，避免统计歧义）
- **连段（combo）**：从 idle 起手，连续触发动词链且中途不回到 idle 的一段操作。
- **中断（drop）**：链中因以下任一原因断掉：
  - 攻击 whiff（落空且无后续取消）
  - 被击退/硬直打断
  - 输入丢失（按了没反应）
  - 取消窗外误触导致动作重启
- **中断率** = 中断次数 ÷ 总连段次数（每次「尝试起一套连段」计 1 次）。

| # | 玩家 ID | 总连段数 | 中断数 | 中断率 | 主要中断原因 |
|---|---|---|---|---|---|

| 20 |  |  |  |  |  |
| **合计** | 20 人 | **Σ总** | **Σ中断** | **Σ中断÷Σ总** | — |

### B.3 阈值与动作
- 队列中断率 **<5%** → S1-06 **PASS**，把上表贴进「B.5 结果」并归档。
- 队列中断率 **≥5%** → 回 Part A（SPIKE-3）/ `VerbDefinition.tres` 帧数调参，重测。
- 不足 20 人时：先记录现有样本，标注「样本不足」，等凑齐再判。

### B.4 给试玩人的极简指引（可贴在测试机旁）
> 「自由连招 5 分钟，想怎么连怎么连。我们只数你『起手一套连段却在中途断掉』的次数。
> 不用追求华丽，正常打就行。」

## 附：已知约束（试玩时注意）
- 本机引擎为 **Godot 4.7-stable**（目标 CI 4.7.1），GDScript 行为一致，试玩体验即最终体验。
- `attack_power` 暂未接入伤害公式（S1 核心伤害走 `defense` 默认 100 透传，向后兼容）；抽卡角色五维已注入 `max_hp/hp/defense/move_speed/resonance_affinity`，但 `attack_power` 实际生效留待后续专项，不影响手感试玩。
- 敌人 AI（S4-01~05 全史诗）已闭环，试玩时敌人会 telegraph（THREAT 色预警）→ 可被完美格破防 → Boss 分阶段无即死，可顺带验证联动。
